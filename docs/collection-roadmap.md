# Torima Auto → ポイ活統合回収マネージャー 開発方針

## 最終目標
ユーザーが対象アプリと回収対象を選び、一度「開始」を押せば、各アプリの指定した報酬回収を可能な限り無人で実施し、完了／未完了を正確に報告する。アプリ単位でも全アプリ一括でも実行できる。実際の所要時間を測定して全体3時間以内を目標に優先順位を決める（成功と3時間以内は保証できない）。

## 不変の設計原則
1. 押せたことと回収完了は別。残回数や完了表示など端末画面で確認可能な証拠で完了を判定。
2. 不明画面・ガチャの×には触れない。広告との区別がつかなければ未完了として安全停止。
3. 学習済み操作も状態別に制限する。類似した画面というだけでは押さない。
4. タスクごとに開始条件、進捗証拠、完了条件、復帰手順、停止条件を明確に定義。
5. 無人実行と全件成功は別。失敗の際も嘘の完了表示をしない。
6. ポイントアプリ・広告サービスの規約、Androidの権限・動作制約を確認する。
7. アクセシビリティ画面操作は通常は画面表示中に行う。画面消灯中の操作は別途要検証。

## 第一段階（v2.4）
タスクID: torima.tank_video
管理対象: トリマのタンク動画回収のみ（ほかの回収対象は未登録）

- CollectionTaskPolicy で、HOMEの「あとN回獲得できます」を解析
- 選択済み move タブと「または」の表示があるHOME画面を進捗証拠とする
- 残り0回を1.7秒以上離して2度以上確認した場合のみ完了
- 回数の減少は画面に表示された「観測差分」であり、獲得マイルや報酬成功数とは断定しない
- CollectionRunStore は実行セッションと直近30件の結果を保存
- 実行時間、残回数、観測減少数、Playへの復帰回数、停止理由を記録
- 最大実行時間は安全のため3時間。時間切れは未完了
- 実行結果を COMPLETED / FAILED / STOPPED / INTERRUPTED と区別

## 未対応（完成形では必須）
- トリマ内の指定可能な全回収対象とON/OFF
- タンク以外の個別の回収完了証明
- 複数ポイントアプリの自動切り替え・一括実行
- タスク時間予測と優先順最適化
- 画像認識による非アクセシビリティ広告の判定
- 画面消灯中や完全バックグラウンドでのタップ

## 次の開発順
1. トリマの回収対象をすべて洗い出し、種類ごとの成功画面・終了条件を収集
2. 共通の操作エンジンとアプリ別アダプターを分離
3. 再試行可能／次タスクへ移動／停止の3分類に基づくタスクキューを導入
4. タスクごとの実績時間、成功率、推定所要時間を保存。優先順位と制限時間を設定
5. 各サービスの許容範囲を確認して2つ目のアプリを追加
6. 一括実行・個別実行・実績表示を統合

重要: 状態が分からないのに「すべて完了」と表示しない。既存のガチャ演出と広告終了を区別する保護は今後も維持する。
