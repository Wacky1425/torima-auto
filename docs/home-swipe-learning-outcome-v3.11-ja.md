# Torima Auto v3.11 — HOME短い下スワイプ復旧と学習結果の誤保留修正

## 実機からの報告
- HOMEの紫ボタンが押されたように反応するのに遷移しないとき、少しだけ下へスクロールすると、その後の紫ボタンのタップで進めることがある。端末の再起動やタスクキルより前に一度試したい。
- 学習モードのタップ後に、Google Playの商品紹介シート（例：ホワイトアウト・サバイバル）が開くことが多い。この画像は学習後の画面であり、勝手に開いたPlay画面自体を学習したいのではない。
- v3.10のTeachOverlayは遷移先がGoogle Playでも変更を記録するが、登録処理でトリマが前面にいることを再度要求するため、元の閉じる操作が適切であっても保留扱いになった。

## HOMEの新しい復旧順序
1. HOMEの紫ボタンを通常の操作で最大2方式試す。ジェスチャー成功は動画の開始とみなさない。
2. 7秒間確認してもHOMEのままなら、1回だけ短い下方向のスワイプを実行（約120px/340ms、紫ボタンの少し上、ボタンと交差しない経路）。
3. 少し待って現在のHOME画面とボタン位置を再解析。新しい座標を使って110msのタップを1回だけ再試行する。古い座標や未知画面へは押さない。
4. それでも画面が変わらなければ、従来のトリマのアプリ情報→強制停止→再起動を1回だけ試す（有効設定のとき）。
5. スワイプ・タップ・画面遷移・再起動の理由をHOME診断に残す。上限3時間と復旧回数の制限を維持する。

## 学習結果の変更
1. 教えたボタンを押した結果は、学習タップ完了直後に評価して保存する。後から「登録」を押したときに前面アプリがPlayになっていても再判定で失敗にしない。
2. 学習元が十分に識別できる安全な操作で、実際に画面が変化した場合は通常の自動操作ルールとして登録。
3. Play商品シートへ移動した場合も、学習元の対象が正確な×／閉じる／dismissボタンで、タップ前に元画面を識別できたときだけ正式登録可能にする。インストール／商品リンク／シェア／券の使用は自動ルールに昇格しない。
4. Google Playサービスが表示するPlayシートでは、インストールボタンがノードに見えなくても、「Google Play」＋「Play Pass」「アプリ内課金」等の表示があればPlayシートと認識可能にする。
5. 以前の保留例のうち、画面識別情報2個以上／明確なdismissボタンID／閉じる範囲／画面変化／外部遷移がそろったものだけ起動時に再分類する。それ以外の保留例は保持。
6. 保留の原因（元画面が疎、閉じる対象を一意に識別できない、外部の別画面が原因など）を具体的に表示する。

## 注意点
- ×を押した結果Playシートへ移動したというだけでは、広告視聴完了や報酬獲得の証拠にはならない。学習の登録と広告からの復帰は別の処理。
- Playからトリマへの復帰は従来の復旧処理を利用。端末で正しく動くかは実機確認が必要。
- 学習元にノードがなく画面特徴も確認できなければ、無条件で自動登録しない。v3.10からの端末内画像×認識は引き続き有効。
- 下スワイプがHOME問題を改善するかは今回の実機テストで判断する。

## 次の確認
v3.11でHOME失敗時の「下スワイプ→紫ボタン再タップ」を確認。さらに、広告の×で学習し、Play画面へ移動した場合に「登録」で自動ルールとして保存されるか検証する。ノードがないものは保留理由とZIPを確認する。
