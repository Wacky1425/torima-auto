# Torima Auto v3.3 — 広告終了直後のガチャ読み込み保護

## 発生していた問題
ガチャ結果のあと広告動画が再生されても、前の `AWAIT_REWARD` が残り、広告右上に `Skip` / `×` があっても150秒待って停止することがあった。
また、広告終了操作後に一時的に表示される下側の×は、ガチャの読み込みをキャンセルする恐れがあった。

## 改善
- **ガチャ直前を保護**: 広告の終了/進行操作（Skip、×、確認済みの広告操作）から **4秒間だけ** 全自動タップを保留する。
- 4秒が経過しただけではタップしない。現在の画面を再取得し、実際の次画面の操作が安定していることを確認する。
- 続きの広告が出た場合も、広告のUI情報・学習済み完全一致などの根拠を再確認し、**約1.7秒安定**したらガチャ待機を理由に長時間ブロックせず進める。
- ガチャの次画面なら従来どおり3秒安定を確認してから進める。
- Meta広告の「Ads served by Meta」「Ad N of M」「Skip」「Close Ad」「詳しくはこちら」等の組み合わせで広告を識別し、広告中のSkipとトリマのスキップ券を区別する。
- ガチャ結果後に次の実際の広告だと確認できた場合は、古い `AWAIT_REWARD` を解除する。
- スクリーンショット認識のタップも、操作回数と連続実行間隔を記録し、再操作を抑制する。

## 安全条件
- 不明画面、ガチャ演出、読み込み中の×は、待機時間だけを根拠に押さない。
- 「友達にシェアする」「スキップ券を使う」は引き続き自動操作しない。
- タップ命令が通ったことと報酬を回収できたことは別として扱う。
- AndroidのUI構造だけでは広告終了か読み込み中か確認できない場合は、誤操作より安全停止を優先する。

## 確認項目
1. ガチャ結果のあと動画広告が表示されたら、右上のSkip/×を認識して再開すること
2. 広告終了から4秒間は、下部に出た一時的な×を押さないこと
3. 4秒後、新しい広告であると確認できれば待機を解除すること
4. 動画広告内で背景映像が動いても操作マークを継続判定すること
5. 新しい報酬画面に進んだとき、二重クリックせず回収を続けること
