# Torima Auto v3.12.2 — HOMEの初回失敗でスクロール / 学習は本物の指タップ

## HOME復旧の優先順位
1. 紫の動画ボタンを通常の自動操作で1回押す。
2. 約3.8秒経ってもHOMEなら、別方式の2回目を打つ前に約120px・340msの短い下方向スワイプを1回だけ実行。
3. スワイプ後にHOMEの紫ボタンを再検出し、上下の移動量を診断に記録。古いタップ座標を使わず、現在のボタン位置で110msのタップを1回だけ行う。
4. まだHOMEから進まなければ、既存の強制停止・再起動を1回だけ試す。タップの成功は画面遷移があった場合だけ判定。
5. ボタンが移動したかを画面ノードの境界から判断する。移動していない場合も画面を読み直してから再タップする。「入力が完了したこと」と「画面のスクロールが実際に起きたこと」は別に診断する。

## 学習モードの修正理由
v3.12.1までは全面の学習オーバーレイが初回の指タップを奪い、その位置へAccessibilityServiceが合成タップを送り直していた。このためユーザーの指なら反応するアプリでも、学習中は自動入力経路のため反応しないことがあった。

## 新しい学習の操作
1. 操作バーの「学習」を選ぶ。コンパクトバーは隠れ、画面上に透明な選択レイヤーだけが残る。左上の大きな説明枠と暗い膜を廃止。中止は画面下中央の小ボタン。
2. 1回目のタップは**位置指定のみ**。選択レイヤーを取り除き、ノードの候補を特定して、必要なら**タップ前の**スクリーンショットで画像特徴を作成する。
3. オーバーレイも操作バーも隠したまま、短いToastで「同じ位置をもう一度指で押してください」と案内。
4. **2回目は本人の実際の指でトリマを直接操作。アプリ側へ合成タップを送らない。**
5. 約14秒間、対象ノードのクリックイベントまたは現在の画面の遷移を受動的に観察。イベント／画面変化を確認できたら、前のノード／画像特徴ルールと実際の画面結果を一緒に保存して操作バーを戻す。
6. 14秒経っても指操作の結果を確認できなければ、学習失敗の理由を表示し、ルールや保留例を増やさない。
7. 「画像に記録されているタップ位置」と「実際にアプリが指タップに反応したこと」を区別できるようになる。

**注意:** アクセシビリティサービスからは他アプリへの指の生MotionEventを一般に取得できないため、指操作の結果はクリックイベント（表示される場合）または画面遷移から推定する。端末でこれらが観測できない場合には、指で押せても学習できないことがある。今後その場合は画像による画面変化を補助判定として検討する。

## テスト
ホーム紫ボタンを1回押しても動かない状態で、次の入力が短い下スワイプ→最新の紫ボタンの押し直しか確認する。学習では「位置指定→膜が消える→指で本体を押す→登録結果が操作バーに出る」の2段階となる。
